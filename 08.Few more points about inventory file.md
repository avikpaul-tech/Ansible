# Ansible Inventory – Different Ways to Define Managed Nodes

An Ansible inventory is a file that contains information about the managed nodes (servers) that Ansible will connect to and manage. It defines server addresses, groups, and host-specific variables.

Ansible supports different inventory formats, but the INI and YAML formats are commonly used.

## 1. Using IP addresses

We can directly specify the IP addresses of managed nodes.

Example: `hosts.ini`

```
[db_servers]
192.168.29.122
192.168.29.123
```

Explanation:

- `[db_servers]` – Defines an inventory group.
- `192.168.29.122` and `192.168.29.123` – IP addresses of managed nodes.
- Both servers belong to the `db_servers` group.

Execute:

```
ansible db_servers -m ping
```

## 2. Using actual hostnames

Instead of IP addresses, we can specify the actual hostnames of managed nodes.

```
[db_servers]
asnmn1
asnmn2
```

Explanation:

- `asnmn1` and `asnmn2` are the actual Linux hostnames.
- **The control node must be able to resolve these hostnames through DNS or `/etc/hosts`.**

Execute:

```
ansible asnmn1 -m ping
```

## 3. Using inventory aliases with IP addresses

We can assign our own meaningful names (aliases) to managed nodes instead of using their actual hostnames.

```
[db_servers]
orcl-db01 ansible_host=192.168.29.122
orcl-db02 ansible_host=192.168.29.123
```

Explanation:

| Entry          | Meaning                                         |
| -------------- | ----------------------------------------------- |
| `orcl-db01`    | Inventory alias chosen by us                    |
| `ansible_host` | Actual IP address used to connect to the server |

The actual Linux hostname does not need to match the inventory alias.

Execute:

```
ansible orcl-db01 -m ping
```

## 4. Using host variables

We can define additional variables for individual managed nodes directly in the inventory file.

```
[db_servers]
orcl-db01 ansible_host=192.168.29.122 db_unique_name=ORCL oracle_sid=ORCL
orcl-db02 ansible_host=192.168.29.123 db_unique_name=TESTDB oracle_sid=TESTDB
```

Explanation:

- `ansible_host` – IP address or DNS name used for the connection.
- `db_unique_name` – Custom variable representing the Oracle database unique name.
- `oracle_sid` – Custom variable representing the Oracle SID.

These custom variables can be referenced inside Ansible playbooks.

## 5. Using inventory groups and parent groups

We can organize managed nodes into logical groups based on their roles or database architecture.

```
[db_standalone]
orcl-db01 ansible_host=192.168.29.122

[db_rac]
rac-node01 ansible_host=192.168.29.123
rac-node02 ansible_host=192.168.29.124

[oracle_servers:children]
db_standalone
db_rac
```

Explanation:

- `[db_standalone]` – Group containing standalone database servers.
- `[db_rac]` – Group containing RAC database servers.
- `[oracle_servers:children]` – Creates a parent group containing both child groups.

Now we can execute commands against all Oracle servers:

```
ansible oracle_servers -m ping
```

Or target only RAC servers:

```
ansible db_rac -m ping
```

## 6. Using YAML inventory format

Ansible also supports YAML inventory files.

Example: `hosts.yml`

```
all:
  children:
    db_servers:
      hosts:
        orcl-db01:
          ansible_host: 192.168.29.122
        orcl-db02:
          ansible_host: 192.168.29.123
```

Explanation:

- `all` – Root group containing all inventory hosts.
- `children` – Defines groups within the parent group.
- `db_servers` – Logical group for database servers.
- `hosts` – Lists individual managed nodes.
- `ansible_host` – Specifies the actual connection address.

To use this file, specify it in `ansible.cfg`:

```
[defaults]
inventory = ./inventory/hosts.yml
```

## Quick reference

| Method              | Example                                 | Purpose                                  |
| ------------------- | --------------------------------------- | ---------------------------------------- |
| IP address          | `192.168.29.122`                        | Direct connection using IP               |
| Actual hostname     | `asnmn1`                                | Connection using DNS/hostname resolution |
| Inventory alias     | `orcl-db01 ansible_host=192.168.29.122` | Friendly name for a server               |
| Host variables      | `db_unique_name=ORCL`                   | Store server-specific information        |
| Group inventory     | `[db_servers]`                          | Organize servers                         |
| Parent-child groups | `[oracle_servers:children]`             | Combine multiple groups                  |
| YAML inventory      | `hosts.yml`                             | Define inventory using YAML syntax       |

**Recommendation:** For Oracle DBA automation, use inventory aliases, host variables, and logical groups. This makes it easier to manage standalone databases, RAC clusters, production, test, and development environments as your infrastructure grows.
