Login as ansible user in the control node
Create required directories
```bash
mkdir -p ~/ansible-oracle/{inventory,group_vars,host_vars,playbooks,roles}
```
Create the config file
```bash
cat << 'EOF' > ~/ansible-oracle/ansible.cfg
[defaults]
# Inventory source path
inventory = ./inventory/hosts.ini

# Remote connection defaults
remote_user = ansible
host_key_checking = False
forks = 10
timeout = 30

# Explicit Python interpreter on managed nodes
interpreter_python = /usr/bin/python3.6

# Playbook output formatting
stdout_callback = yaml
bin_ansible_callbacks = True

# Disable retry files
retry_files_enabled = False

[privilege_escalation]
become = False
become_method = sudo
become_user = root
become_ask_pass = False

[ssh_connection]
# Pipelining reduces SSH operations for faster execution
pipelining = True
ssh_args = -o ControlMaster=auto -o ControlPersist=60s -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null
EOF
```
Verification: Run ansible --version from ~/ansible-oracle. The output line config file = must point to /home/ansible/ansible-oracle/ansible.cfg.


## Explanation of the config file content
This `ansible.cfg` file controls how Ansible behaves whenever you run commands from inside your `ansible-oracle` project directory. It is organized into three standard sections: **`[defaults]`**, **`[privilege_escalation]`**, and **`[ssh_connection]`**.

---

### 1. `[defaults]` Section

This section defines core operational defaults for your project.

* **`inventory = ./inventory/hosts.ini`**
Tells Ansible where to find your list of managed hosts by default. Because this is set, you don't need to pass `-i ./inventory/hosts.ini` every time you run a command or playbook.
* **`remote_user = ansible`**
The default Linux user account Ansible uses to establish initial SSH sessions to your managed database nodes.
* **`host_key_checking = False`**
Disables the interactive SSH prompt asking whether to trust new host keys (`"Are you sure you want to continue connecting (yes/no)?"`). This prevents automated scripts from hanging on newly added servers.
* **`forks = 10`**
The number of parallel processes Ansible spawns to manage target nodes simultaneously. The default is `5`. Setting it to `10` allows Ansible to manage up to 10 database hosts in parallel without queuing.
* **`timeout = 30`**
The number of seconds Ansible waits for an SSH connection to establish before timing out and flagging the host as unreachable. The default is typically `10` seconds; `30` gives slower or heavily loaded DB hosts extra room to respond.
* **`interpreter_python = /usr/bin/python3.6`**
Explicitly instructs Ansible to run its remote modules using `/usr/bin/python3.6` on the target nodes. This silences the Python auto-discovery warnings and prevents Ansible from falling back to the legacy Python 2.7.5 installed on Oracle Linux 7.
* **`stdout_callback = yaml`**
Changes the terminal output format of playbooks from dense, single-line JSON strings to readable, indented YAML. This makes reading output, command logs, and errors much easier during troubleshooting.
* **`bin_ansible_callbacks = True`**
Ensures formatting callbacks (like `stdout_callback = yaml`) apply to both standard playbooks and ad-hoc commands (e.g., `ansible -m ...`).
* **`retry_files_enabled = False`**
Prevents Ansible from creating `.retry` files in your project directory whenever a playbook fails on a host. This keeps your project folder clean.

---

### 2. `[privilege_escalation]` Section

This section governs how Ansible handles `sudo` and root switching.

* **`become = False`**
Sets privilege escalation to **off by default**. This ensures tasks run as the unprivileged `ansible` user unless a specific playbook or task explicitly declares `become: true`. This prevents accidental execution of safe read-only tasks as root.
* **`become_method = sudo`**
Specifies the privilege escalation tool to use (standard Linux `sudo`).
* **`become_user = root`**
The default target account when `become: true` is invoked without a specific user. (In your playbooks, you override this per task using `become_user: oracle` or `become_user: grid`).
* **`become_ask_pass = False`**
Tells Ansible not to prompt you for a `sudo` password at the terminal, relying on the `NOPASSWD` entry you added to `/etc/sudoers.d/ansible`.

---

### 3. `[ssh_connection]` Section

This section tunes low-level OpenSSH performance and network behavior.

* **`pipelining = True`**
Significantly speeds up execution. By default, Ansible copies a module file to the remote server's temp directory over SFTP/SCP, executes it, and deletes it. With `pipelining = True`, Ansible executes Python modules by piping code directly into the remote Python interpreter via SSH stdin without writing temporary files to disk, cutting network round-trips. *(Requires `requiretty` to be disabled in `/etc/sudoers`, which is the default in EL7).*
* **`ssh_args = -o ControlMaster=auto -o ControlPersist=60s -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null`**
Custom flags passed directly to the system `ssh` command:
* **`ControlMaster=auto` & `ControlPersist=60s`:** Enables SSH connection multiplexing. The first task creates a master SSH socket to the target host; subsequent tasks reuse that open channel for the next 60 seconds instead of completing a new TCP and SSH handshake for every single task.
* **`StrictHostKeyChecking=no` & `UserKnownHostsFile=/dev/null`:** Bypasses host key verification and prevents host keys from being written to your local `~/.ssh/known_hosts` file. This prevents failures when hosts are re-imaged or their IP addresses change.
